# 项目制作器 MVP｜Windows 验收清单

## 1. 获取与本地构建

1. 切换到 `project-builder-cross-platform` 分支并拉取最新代码。
2. 确认本机安装 Python 3.11 x64。
3. 双击 `headphone-dashboard-sample\project-builder\build-windows-exe.bat`。
4. 构建脚本必须先通过 Python 自动化测试，再产生：

```text
headphone-dashboard-sample\project-builder\dist\EarphoneProjectBuilder\EarphoneProjectBuilder.exe
```

5. 保存脚本最后打印的文件大小和 SHA-256。正式 EXE 必须来自这台本地 Windows 机器，不使用 GitHub Actions artifact。

## 2. 新建项目验收

1. 双击 EXE。
2. 选择“新建项目”，填写项目名、CSV、照片根目录和输出根目录。
3. 在“CSV 与变量类别”检查前 200 行原表预览。
4. 至少更换两个字段类别，例如把一个数值字段改为“评分 / 数值指标”，再把一个字段改为“忽略”。
5. 点击“恢复全部自动类别”，确认可以恢复；随后重新完成需要的人工分类。
6. 在“照片规则”分别检查用户、耳侧、设备字段和视角顺序。
7. 点击“重新扫描并生成映射预览”。
8. 发布项目，并在原看板打开生成的 JSON。

通过标准：看板无需转换即可读取；人工变量类别与制作器一致；看板中仍可再次更换变量类别并保存。

## 3. 照片映射验收

至少选择一个包含左右耳、两台设备和多个视角的用户：

- 每个槽位能看到真实缩略图、设备、耳侧、视角和相对路径。
- 点击缩略图能打开原图。
- 缺失、过多和未使用照片可以被发现。
- 从下拉框为单槽位改图或清空。
- 勾选两个槽位并交换。
- 对设备照片组执行上移和下移。
- 执行左右耳互换。
- 把空耳或补拍照片重新分配到槽位。
- 恢复当前用户自动映射，再恢复全部自动映射。
- 人工调整后发布，关闭并重新打开项目，结果不丢失。

## 4. 更新隔离验收

建议先复制一份已发布项目作为测试样本。

### 仅更新 CSV

- 选择新 CSV，不选择外部照片目录。
- 发布前记录 `photos` 目录文件数量和哈希。
- 发布后照片字节不变，分析配置与备注不变。
- 相同用户/设备/耳侧的原照片映射保留。

### 仅更新照片

- 原始 CSV 文件字节不变。
- 新照片合并进入项目；项目原有但本次来源中没有的照片不删除。
- 自动映射基于新照片重算，有效人工映射保留。

### CSV + 照片

- 两类变化在同一次确认后生效。
- 制造候选包校验失败时，原项目仍能被看板打开。

### 仅更新映射

- CSV 和照片文件均不发生复制、替换或删除。
- 只改变项目 JSON 内映射结果及映射覆盖。

## 5. 看板保留功能回归

在未使用独立制作器的情况下，直接进入看板首页确认：

- 仍可读取原始 CSV、项目 JSON 和照片目录。
- 仍可自动识别变量类别并人工更换、确认和恢复。
- 仍可运行顺序/文件夹照片映射。
- 仍可查看缩略图、替换照片、交换槽位、移动设备组、互换左右耳和调整空耳照片。
- 仍可保存项目并继续进入分析页面。

任何一项缺失，都属于 MVP 阻断问题。

## 6. Linux CLI 对照

Windows GUI 验收通过后，在 Linux x64 使用同一输入执行：

```bash
cd headphone-dashboard-sample
PYTHONPATH=project-builder python3 project-builder/native_entry.py build \
  --config project-builder/project-builder.config.example.json \
  --dry-run --json
```

通过标准：无需 X Server；退出码正确；JSON 语义、照片字段和资产清单与 Windows GUI 输出一致。
